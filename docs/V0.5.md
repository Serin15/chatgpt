# PULSE v0.5 — interpretarea știrilor cu citări

Modul AI opțional în dosarul fiecărui activ: **Ce spune știrea, de fapt?**. Pornește oprit.
Nu există încă un model instalat sau o cheie furnizată în mediul cloud. Nu prezentăm răspunsuri
de test ca analize reale și nu declarăm o precizie măsurată.

## Ce face

1. Citește o pagină HTTPS din catalogul v0.4, fără redirecturi, scripturi sau linkuri urmate automat.
2. Trimite modelului text public limitat, sursa/data/amprenta, identitatea activului și observațiile
   tehnice despre contract. Dacă vii dintr-o știre, include separat titlul, marcat ca metadata.
   Nu trimite solduri, ordine, portofoliul, cheia API sau notițele personale în prompt.
3. Cere rezumat în română, afirmații relatate, explicația relației cu moneda, întrebări de cercetat
   și riscuri. Fiecare afirmație și explicație cere un citat literal din documentul citit.
4. Respinge JSON incompatibil, surse/citate inventate și câteva forme explicite de promisiuni de
   randament. Nu urmează instrucțiuni de instrumente propuse de model și nu îi oferă instrumente.
5. Păstrează propunerea modelului. O relație pozitivă de emitere/listare este redusă la dovezi
   insuficiente dacă identitatea, contractul, chain-ul, contextul negativ sau rolul sursei o contrazic.
6. Salvează modelul/furnizorul, versiunea promptului, textul trimis, SHA-256 al paginii originale,
   citările, utilizarea de tokenuri raportată și erorile. Semnalele paper păstrează copia originală.
   Analizele din feed sunt legate de exact activul și ID-ul canonic al știrii.

Citările sunt verificate **ca prezență a textului**, nu ca susținere semantică sau adevăr. Un model
poate interpreta greșit un citat real. Întrebările și riscurile sunt text generat, nu fapte validate.
Etichetele pozitive rămân ipoteze. `claim_verified`, `endorsement_verified` și
`fundamentals_verified` rămân false; AI nu completează automat dosarul manual și nu modifică
regulile, calculele financiare sau comenzile paper. Nicio predicție de profit validată.

## Configurare pe Windows

În dosar, deschide **Configurează motorul AI**, alege furnizorul și numele exact al modelului,
salvează, apoi **Testează conexiunea AI**. Testul confirmă numai vizibilitatea modelului, fără
generare plătită; analiza documentului verifică ulterior generarea și citările.

**Ollama local:** instalează aplicația de la [ollama.com](https://ollama.com/) și un model care
suportă conversație și JSON structurat. Verifică `ollama list`; copiază exact numele listat.
Serviciul trebuie să ruleze pe același PC cu PULSE la portul 11434. Modelul nu este instalat automat.
Alege dimensiunea în funcție de RAM/VRAM și verifică viteza/limba română. PULSE cere context de
16.384 tokenuri și maximum 2.200 tokenuri generate; o mașină lentă poate depăși timeout-ul de
citire de 180 secunde. Nu există încă un model local validat sau recomandat pe PC-ul utilizatorului.

**OpenAI API:** necesită cont/credit API separat de abonamentul ChatGPT, un model accesibil care
suportă Responses API și Structured Outputs și cheia în variabila `PULSE_AI_API_KEY` din mediul
procesului. `OPENAI_API_KEY` existentă este acceptată ca alternativă locală. Nu scrie cheia în
fișiere tracked, chat sau formularul UI. Într-un PowerShell separat o poți introduce fără ecou:

```powershell
$pulseCredential = Get-Credential -UserName "pulse-api" -Message "Cheia API în câmpul Password"
$env:PULSE_AI_API_KEY = $pulseCredential.GetNetworkCredential().Password
.\start-windows.cmd
Remove-Item Env:\PULSE_AI_API_KEY
Remove-Variable pulseCredential
```

Acest fragment este documentat, fără execuție nativă Windows aici. Fișierul `.env` nu este încărcat
automat. Nu am validat live OpenAI: lipsește cheia, iar documentația externă OpenAI/Ollama nu a
putut fi citită din acest cloud. Compatibilitatea HTTP/schema este acoperită cu transport simulat.
La configurare reală verifică modelul, documentația actuală, accesul și prețurile furnizorului.
Clientul cere `store=false`, fără a afirma că aceasta înlocuiește politica de retenție a furnizorului.

Configurația fără secrete se păstrează în SQLite și backup. Variabilele `PULSE_AI_PROVIDER` și
`PULSE_AI_MODEL`, dacă sunt setate, au prioritate și blochează modificarea configurației din UI.
URL-urile motoarelor sunt fixe, fără endpoint arbitrar introdus în browser.

## Limite operaționale

Analiza AI pornește **manual**, separat de colectarea automată a știrilor. Implicit maximum 20 de
încercări de generare pe zi UTC, configurabil 1–1000, cu rezervare atomică în SQLite. Încercările
eșuate consumă limita; nu există retry automat. Maximum o analiză simultană per proces PULSE.
Limita este pentru cereri, nu un plafon monetar; facturarea se verifică la furnizor. Un timeout
local nu garantează că furnizorul a oprit procesarea sau facturarea.

Documentul poate fi parțial, pagina dinamică poate fi incompletă, sursa poate greși. Rezultatele
mai vechi de 24h sunt marcate pentru reluare. O generare eșuată rămâne vizibilă și nu este înlocuită
cu un rezultat vechi. Nu există încă triangulare independentă, verificarea conturilor sociale
originale, procesare AI automată în fundal sau un benchmark reprezentativ pentru piață.

## Evaluare reproductibilă

[Setul inițial](evaluation/news-cases.json) are 12 cazuri: **două extrase observate** de pe Solana
și Kraken, cu URL/data/amprenta paginii și **zece scenarii sintetice** marcate explicit. Acoperă
emitere/listare fictive, nume asemănător, negare, contract/chain diferit, persoană publică,
instrucțiuni malițioase în document și identitate necunoscută. Etichetele sunt ale autorului,
nu sunt revizuite independent. HTML-ul original complet nu este arhivat.

Verificare offline, fără model, fără cost și fără modificarea datelor utilizatorului:

```bash
uv run python -m app.ai_evaluation
```

Rulare explicită cu un motor instalat/configurat; OpenAI poate genera costuri:

```bash
uv run python -m app.ai_evaluation --run-model --provider ollama --model NUMELE_EXACT --output data/evaluation/local.json
```

Pentru API folosește `--provider openai` și numele disponibil în cont. Evaluarea este separată
de limita zilnică a aplicației: maximum 20 de cazuri per invocare, fără retry, cu bază temporară.
Raportul păstrează fiecare eșec, clasificările, citările, utilizarea raportată, asocierile pozitive
false, precision/recall pentru pozitive și baseline-ul „mereu dovezi insuficiente”. O ieșire
invalidă contează ca eșec, nu este scoasă din numitorul accuracy. Un set mic/sintetic nu dovedește
precizia în piață; sunt necesare cazuri reale de anunțuri autentice și false, revizuite independent,
un set separat de test și rulări forward înainte de activarea automată.
Runnerul iese cu cod nonzero dacă există cazuri eșuate sau clasificări care nu corespund etichetelor.

[Raportul inclus](evaluation/manifest-validation.json) validează numai structura setului:
`model_run=false`, `metrics=null`. Niciun model nu a rulat evaluarea reală în această livrare.
